  - Validar que el usuario autenticado es propietario del ecosistema.
  - Devolver el ecosistema actualizado en la respuesta.
- Añadir endpoint DELETE /ecosystems/:id (o POST /ecosystems/:id/revoke) para dar de baja/revocar el ecosistema.
  - Validar que el usuario autenticado es propietario.
  - Marcar el ecosistema como status REVOKED en lugar de eliminarlo físicamente de la bd y anonimizar sus datos usando el uuid.

services/iot-manager
- Añadir endpoint GET /iot/devices/:deviceId/last-interaction.
  - Consultar la última entrada registrada del dispositivo en la base de datos/telemetría.
  - Devolver un objeto con `lastInteractionAt` en formato ISO 8601.
- Garantizar que el servicio puede buscar rápidamente la última interacción por deviceId.
- Opcional: normalizar el resultado si no hay interacción registrada (404 o { lastInteractionAt: null }).
- En la siguiente iteración, permitir que la UI determine `ONLINE` si la última interacción es <= 5 minutos.

Notas generales
- El frontend ya está preparado para usar `/iot/devices/:deviceId/last-interaction` y mostrar ONLINE/OFFLINE en el modal.
- En la próxima iteración se debe alinear el backend para soportar la edición y revocación de ecosistemas junto con el estado de conexión de dispositivos.
